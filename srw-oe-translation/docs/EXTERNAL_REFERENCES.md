# External references

These are research references, not authorities for the game's exact binary layout.

- [retro-trans/SRW-Z](https://github.com/retro-trans/SRW-Z) — workflow and QA inspiration for a different PS2 title, and (confirmed by the user, 2026-10-09) the model for this project's end deliverable: **the whole game translated to English and shipped as an `.xdelta` patch** the user applies to their own Japanese image (`xdelta3 -d -s source.iso patch.xdelta out.iso`, or DeltaPatcher / the Retro Trans desktop app). Its pipeline maps to ours: `extract_script.py` (extract every string to editable JSON) ≈ our extraction + text-unit export; translate the `text` fields ≈ our translation phase; `apply_script.py` (write back with an exact round-trip: extract, change nothing, apply, byte-identical) ≈ our reinsertion + container rebuild; gates before every build (`verify_pointers.py`, `verify_elf_patches.py`, `integrity.py`) ≈ our listing check + table check; patch packaging ≈ our planned xdelta builder. Do not reuse its game-specific parsers as if they applied to PSP OE.
- [YACpkTool](https://github.com/Brolijah/YACpkTool) — CPK extract/pack utility used by the user. Its archived README documents `-L` (list), `-X` (extract), `-P` (pack), `-i` (input path), `-o` (output), and `-d` (directory); packing defaults to codec `none`, with LAYLA available. It labels `-R` file replacement experimental. This is a candidate local adapter only: exact executable/version, `.EDAT`-named input handling, source codec behavior, and no-change repack results must be tested before relying on it. The tool should be supplied locally and pinned/hashed, not downloaded by the pipeline.
- [YACpkTool source, `YACT/Program.cs`, commit `6098bb2001f31b869b32d747f798b044029aa52a`](https://github.com/Brolijah/YACpkTool/blob/6098bb2001f31b869b32d747f798b044029aa52a/YACT/Program.cs) (2017-12-17, archived repository; SHA-256 `94c3454a9ab8a0f36e7daeb75778d4b8af71c5e8e512b1bde34616c434d00db2`). Read to derive the converter assumptions in `tools/run_pipeline.py`: no exit code is set, `Error:` paths return normally, `-o` is checked with `Uri.IsWellFormedUriString`, `-X` takes a file name only when it does not start with `-`, progress uses `Console.CursorLeft`, and stdin is never read. Read only, not executed. Its `CpkMaker.dll` was not analysed.
- [Historical GBAtemp SRW OE thread](https://gbatemp.net/threads/super-robot-wars-oe.351431/) — old discussion of CPK extraction, `.EDAT` naming, inner `.PAC` files, and repacking difficulties. Treat as a lead, not a tested recipe.

Do not link to or include unauthorized game-image/DLC downloads. The game data remains local to the user.
